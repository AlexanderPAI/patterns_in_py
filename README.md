# Обзор моделирования предметной области

_Моделирование предметной области_

Это та часть кода, которая наиболее близка к бизнесу, наиболее подвержена изменениям и представляет наибольшую ценность 
для бизнеса. Делайте ее легкой для восприятия и внесения изменений

_Отличие сущностей от объектов-значений_

Объект-значение определяется его атрибутами. Обычно он лучше всего реализуется как немутируемый тип. Если вы измените 
атрибут объекта-значения, то он будет представлять собой другой объект. Напротив, сущность имеет атрибуты, которые 
могут меняться со временем, и это все равно будет та же самая сущность. Важно определить то, что уникально 
идентифицирует сущность (обычно это какое-то имя или поле ссылки).

_Не все должно быть объектов_

Python - это многопарадигмальный язык, поэтому пусть "глаголы" в вашем коде будут функциями. Для каждого
`FooManager`, `BarBuilder` или `BazFactory` есть более выразительная и читабельная `manage_foo()`, `build_bar()` или
`get_baz()`

# Репозиторий

Паттерн "Репозиторий" используется для обеспечения принципа инверсии зависимостей.
Репозиторий - это упрощающая абстракция хранения данных, которая позволяет устранить связанность слоя модели и слоя 
данных.

Repository находится между моделью предметной области и базой данных.

ORM (объектно-реляционное отображение) существуют для преодоления концептуального разрыва между миром объектов и 
моделирования предметной области и миром
баз данных и реляционной алгебры.

Самая важная вещь, которую дает ORM - **неосведомленность об используемой системе постоянного хранения**: капризная 
модель предметной области не должна ничего знать о способах загрузки или хранения данных. Это помогает держать модель 
независимой от конкретных технологий баз данных.

## Инвертирование зависимости: ORM зависит от модели

В SQLAlchemy есть классическое попарное отображение (Явное ORM с участием объектов Table). 
Наша главная задача - конвертирование между схемой и модельную 
предметной области.


## Хранилище в абстрактном виде

Паттерн "Репозиторий" - это абстракция поверх системы постоянного хранения.

Простейший репозиторий имеет два метода: 
- `add()` - чтобы поместить новый элемент
- `get()` - чтобы получить уже имеющийся

> Почему нет `list()`, `delete()` и `update`?
> В иделальном мире мы модифицируем модельные объекты один за раз, и удаление обычно обрабатывается как
> мягкое удаление - то есть `batch.cancel()`.
> А обновлением занимается паттерн `Unit of Work (UoW)`
