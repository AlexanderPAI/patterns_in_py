# Паттерн "Сервисный слой"

Добавим API, который будет работать с сервисным слоем, а он станет служить точкой входа в модель предметной области.

## Введение сервисного слоя

Извлечение материала из репозитория, проверка входных данных по состоянию базы данных, обработка ошибок и фиксация в успешном результате сценария процесс (happy path) - фактические является _оркестровкой_
Все это не должно быть связано эндпоинтами API.

Поэтому есть смысл разделить сервисный слой на:
- слой оркестровки (orchestration layer)
- слоем вариант использования (use-case layer)
